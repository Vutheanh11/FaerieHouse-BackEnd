# Faerie House Backend

Node.js 22+ API for Faerie House. Run `npm ci`, `npm start`, and `npm test` locally.

The production data store is Neon PostgreSQL (`DATABASE_URL`). It stores members, posts, popup settings, login logs, and uploaded member/popup/News images. Admin changes are visible through the API immediately; they no longer require a GitHub commit or Render redeploy. Existing member photos were imported into `faerie_images` as WebP files. The fixed TP.HCM 2026 event timeline remains in `src/data.mjs`; it is not edited by Admin.

Public endpoints: `GET /api/health`, `GET /api/v1/members?year=2026&campus=hcm`, `GET /api/v1/events?year=2026&campus=hcm`, `GET /api/v1/news?campus=hcm`, `GET /api/v1/popup?campus=hcm`, and `GET /api/v1/{member,popup,news}-images/<id>.webp`. The campus parameter accepts `hcm` (default for legacy clients/data) or `quy-nhon`. Quy Nhơn starts empty and never receives the built-in TP.HCM stories. Existing records without a campus belong to TP.HCM.

Admin accounts are stored in `faerie_admin_users` with salted scrypt password hashes. A `super` admin can manage members, move News posts to a recoverable trash, restore them, edit popup settings, view successful/failed login attempts, and create or manage `editor` and Quy Nhơn `campus_admin` accounts. Account management uses `GET/POST /api/v1/admin/users`, `PATCH/DELETE /api/v1/admin/users/:username`; deletion disables the account and revokes existing sessions. Editors can create drafts, preview/edit/publish News and manage the popup, but cannot manage members/accounts or trash posts. Quy Nhơn campus admins can manage Quy Nhơn members, News, and popup only; Admin API reads are campus-filtered and writes preserve all other campus data. They cannot view or edit TP.HCM data through Admin, view login logs, or manage accounts. Published posts alone appear in the public API; up to 20 prior versions remain on each edited post. The login API throttles repeated failures per client IP. Super admins can enable TOTP two-factor authentication; its seed is AES-GCM encrypted with a key derived from `ADMIN_SESSION_SECRET`. Admins can change their own password, invalidating earlier sessions. Fixed TP.HCM stories in `src/data.mjs` are not database News posts and cannot be edited through Admin.

## Production configuration

In Render **faerienews-backend → Environment**, upload a secret file named `.env.local` containing `DATABASE_URL=<Neon pooled PostgreSQL URI>`. The Blueprint's start command reads `/etc/secrets/.env.local` at runtime. Keep this file and `ADMIN_USERNAME`, `ADMIN_PASSWORD`, and `ADMIN_SESSION_SECRET` secret; never commit them. Alternatively, set `DATABASE_URL` directly as a Render environment variable. When `DATABASE_URL` is present, the API uses PostgreSQL exclusively for mutable data. Without it, the previous GitHub JSON storage remains available as a temporary fallback; `GITHUB_TOKEN` is required only for that fallback and older popup image URLs.

The base schema is in `sql/001_initial.sql`; apply `sql/002_admin_users.sql`, `sql/003_admin_mfa.sql`, and `sql/004_admin_campus.sql` to an existing database before enabling campus admin accounts. Deployment without 003 still permits normal sign-in, but MFA setup cannot finish. Create the initial `super` account separately with a salted hash, never a plaintext password in Git. `scripts/migrate-to-neon.mjs` copies the existing JSON and member/popup images into an **empty** database; it aborts if any database rows already exist. Do not run it again after Admin has made changes. `.env.local` is ignored by Git and must never be uploaded. `GET /api/health` reports `storage: "postgres"` once the live service is connected.

`ALLOW_LEGACY_ADMIN` defaults to `false`, so Render environment username/password no longer grant access. Set it to `true` **only** for a temporary recovery period if there is no working database super admin. Keep `ADMIN_SESSION_SECRET` stable while MFA is enabled: rotating it without first disabling MFA makes stored TOTP seeds unreadable. Use a long, unique database account password; change any initial test password immediately. MFA setup displays a secret to enroll manually in an authenticator app and confirms a six-digit code before activation.

The frontend currently references the same API URL, so no frontend configuration change is needed. Existing JSON files remain in Git as a historical backup; they are not updated after switching to PostgreSQL. The old login log remains in Git history, which matters because this repository is public. Remove/rewrite that history only as a separate, deliberately reviewed security operation.

The IP in login logs is based on the proxy's `X-Forwarded-For` header and may not be reliable. Device text is inferred from the User-Agent; it is not a hardware identity.
